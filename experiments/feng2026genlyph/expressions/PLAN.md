# PLAN — System X (data-driven pictorial glyph designer)

The design (8 processes, no descriptions, no representation descriptions, no references, no images) describes a
pipeline that turns a tabular dataset into a **fragmented glyph visualization (FGV)**:
keywords → candidate pictorial images → pick one → segment it into parts (masks) → map parts to data attributes →
generate categorical variants of parts → numeric encodings of parts → one glyph per data row → lay out glyphs → export.

Default choices taken without waiting for confirmation (per experiment instructions).

## Stack

| Concern | Choice |
| --- | --- |
| Backend | Node 20 + Express (`server/`), plain ESM JavaScript |
| Model provider | Local Claude Code CLI: `claude -p --output-format json --tools "" --no-session-persistence`, spawned with `CLAUDECODE` removed from env. All calls go through one function `callModel()` in `server/llm.mjs`. |
| Images | No image model is available, so every *visual* generated by a model is an **SVG** written by Claude. This makes segmentation (`model_3 extract`) operate on SVG elements, which is fully interactive. |
| Frontend | Vite + React + TypeScript (`web/`), state in one zustand store (`web/src/store.ts`) |
| Persistence | In-memory in the browser session (plus "load sample dataset"). No database. |
| Tests | `node --test` for deterministic tools (CSV parsing, attribute extraction, keyword parsing, SVG sanitizing, layout matching); `tsc --noEmit` for the frontend |

## Transformations

| Process | Step | Implementation |
| --- | --- | --- |
| 1 | tool_1 extract dataset→attributes | `extractAttributes()` web/src/tools/attributes.ts |
| 1 | tool_1 translate attributes→description | `describeDataset()` same file |
| 1 | model_1 generate keywords ~ | POST /api/keywords → `callModel('keywords')` |
| 1 | tool_1 extract keywords | `parseKeywords()` web/src/tools/keywords.ts |
| 1 | tool_1 translate keywords→word cloud | `<WordCloud>` |
| 1 | tool_1 compose image prompts | `composeImagePrompts()` tools/prompts.ts |
| 1 | model_2 generate candidate images ~ | POST /api/image (one call per prompt, parallel) |
| 2 | human specify concept | concept textarea |
| 2 | tool_1 compose image_prompt_2 | `composeConceptPrompt()` |
| 2 | model_2 generate ~ | POST /api/image ×4 |
| 2 | human modify concept (loop) | edit textarea + "Regenerate"; rounds kept |
| 3 | human select glyph image | click a candidate in gallery |
| 4 | human select regions | drag rectangles on the glyph |
| 4 | model_3 extract masks | POST /api/segment (SVG + boxes → element ids) |
| 4 | human modify masks | click elements to toggle membership, rename, delete |
| 4 | human assign mappings | attribute dropdown per mask |
| 5 | tool_2 extract fragments + edges | `extractFragments()` (getBBox) |
| 5 | model_4 generate descriptions ~ | POST /api/describe |
| 5 | tool_1 compose encoding prompts | `composeEncodingPrompts()` |
| 5 | model_5 generate categorical fragments ~ | POST /api/variant per prompt |
| 5 | human modify prompts (loop) | edit prompt + regenerate; versions kept |
| 6 | tool_3 extract contours | `extractContours()` (canvas raster) |
| 6 | human specify assembly settings | settings form |
| 6 | tool_3 translate numerical fragments | `numericalFragments()` |
| 6 | tool_3 compose glyphs | `composeGlyphs()` |
| 6 | human modify settings (loop) | live form, recomposes |
| 7 | human specify placement | form |
| 7 | tool_4 match layout recommendation | `recommendLayouts()` |
| 7 | human select layout | click a recommendation card |
| 7 | tool_3 compose fgv | `composeFGV()` |
| 7 | human modify layout (loop) | edit layout params, recomposes |
| 8 | human specify export | PNG / SVG buttons |
| 8 | tool_3 translate → file | `exportFGV()` |

## Layout

Six tabs (Data & Ideas · Concept & Pick · Segment & Map · Categorical Fragments · Assemble · Layout & Export), each
enabled once its inputs exist. Tabs map 1:1 to processes except tab 1 (process 1) and tab 2 (processes 2+3).

No steps are added beyond the design.
