# PLAN — implementing "System X" from design.json

The design gives only expressions: no goal, no description, no representation descriptions, no references, no images.
The plan therefore first fixes an **interpretation** and then maps every identifier and step onto code.
Per the experiment instructions, every open choice takes the recommended default without waiting for confirmation.

## Interpretation (inferred; the design did not state it)

A **data-driven pictorial chart maker**. The user loads a table (r1). The system summarises it, has a model propose
visual themes, and generates candidate illustrations (SVG) that echo the shape of the data. The user steers and picks one
illustration, segments it into elements with model help, binds elements to data fields, has a model generate per-category
variants of the bound elements, lays them out as data-driven pictorial charts, annotates the chosen chart, and exports it.

Because only the Claude Code CLI is available (no image model), every `visual` medium produced by a model is **SVG markup**
generated by Claude; segmentation (model_3) operates on the SVG's element geometry.

## Stack (default chosen)

- Backend: Node 20 + Express (TypeScript, run with `tsx`). One function `callModel()` in `server/model.ts` wraps
  `claude -p --output-format json` (CLAUDECODE removed from env, `--tools ""`), so the provider can be swapped.
- Frontend: Vite + React + TypeScript, no UI library, plain CSS. State in one `useReducer` store named after identifiers.
- Tools (deterministic code) in `src/tools/*.ts`, shared by the frontend; unit-tested with Vitest.
- Persistence: in-memory + `localStorage` snapshot of the session (no database).

## Layout

A left-hand stepper (1 Data → 2 Ideas → 3 Illustrate → 4 Segment & bind → 5 Variants → 6 Chart → 7 Annotate → 8 Export),
main panel showing the current step. Each step is one process (P1 spans Data/Ideas/first Illustrate generation).

## Choices left open → defaults taken

- Model provider: Claude Code CLI, `sonnet` for SVG, `haiku` for text (env overridable). 
- Visual generation: SVG by Claude (no image model available).
- Persistence: localStorage.
- Sample dataset bundled (fruit sales) plus CSV upload.
- No steps added beyond the design.
